# Stored graph files

`loadGraphFile` from `@tangle-network/agent-runtime/kernel` reads YAML or JSON into canonical `StoredGraph` data. It validates topology and profiles before execution. Pass `source` in loader options to compile exact authored bytes without a temporary file; the path argument still selects YAML/JSON format and the default working directory. `validateStoredGraph(value)` validates untrusted compiled graph data, its digest, profiles and named checks before storage or execution; authoring envelopes belong to the loader. `graphFromStored` binds the named independent completion check; registration with `recordStoredGraphRun(registry, graph)` computes a missing digest without inventing a run record.

A loaded file is `StoredGraph` data whose `check` became a `route` deliverable reference; `graphFromStored(loaded.graph)` (from `/kernel`) binds that check and returns the `AgentGraph` to run (`examples/graphs/debate-rounds.ts` runs both forms). The host starts or attaches CLI Bridge and supplies `{ backend: 'bridge', bridgeUrl, bridgeBearer, cwd }` to `runGraph` or the existing durable `superviseGraphPursuit` entry. Every node uses a Bridge session in that environment. A cloud placement runs the same graph and Bridge inside one Sandbox. The host owns the server lifecycle and credentials.

Graph Bridge execution requests `response_format: { type: 'json_object' }` and requires Bridge's successful `final_output`. Node output is that JSON value; conversation text, tools and usage remain execution evidence. A failed native process cannot deliver a node result. Missing usage remains unknown. A terminal node exposes `failure?: RuntimeFailureCause` on the existing result tree, protected remote observation and durable replay. Read stable `code`, `owner` and optional `providerCode`; `cause` is bounded redacted display text. `all-children-down` remains the run lifecycle reason. A legacy reason alone never supplies a native diagnosis or remedy.

File `params` declare typed defaults; `${params.name}` and `${trigger.name}` bind JSON slots without evaluating code. A whole slot preserves its JSON type. Inserted parameter and trigger values remain literal data, including text such as `${HOME}` or `${trigger.other}`. Compiled graphs carry `triggerBindings`: an explicit list of authored slots still awaiting trigger data; an empty list marks fully bound data. This provenance is included in the graph digest. Rehydration binds only those recorded slots, while hand-authored legacy graphs without the field retain their original trigger-binding behavior. Missing values refuse execution. Runtime node-output substitutions and `call` vertices are not implemented by this file loader yet. Deployment `on` data is returned separately and excluded from the digest.

A node has a canonical `profile`, or `seat` shorthand resolved by the host's `resolveSeat` injection. The loader does not parse model aliases or inspect logins. `seat` in loader options overrides every node, followed by `nodeSeats[id]`, then the file value. Returning `undefined` advances an ordered preference; a resolver error propagates. Resolver context includes `lastCandidate`, true for a sole/global choice, the last ordered preference, or an implicit default, so Bridge can return a structured login refusal only after fallback choices are exhausted. Resolved choices provide canonical harness/provider/model and optional model reasoning effort. Models and grammar come from their owner APIs, never a copied catalog.

`needs` lists provider names. The host supplies canonical `AgentProfile.connections` bindings through loader options `needs`, or optional `resolveNeed(provider, { node, cwd, signal })` for providers without an own static key. Own static bindings take precedence even when invalid; invalid explicit data refuses canonical profile validation and never falls back. A resolver may return a canonical binding or a Promise; only `undefined` produces `GraphFileResolutionError` with code, provider and node, and thrown values propagate unchanged. Authored connections precede resolved needs in file order; equivalent static and callback bindings have the same graph digest. Credentials stay outside graph data.

Parsing and static resolution stay offline by default; injected seat/need resolvers may perform host-owned I/O. For dry-run, omit effectful resolvers and use static bindings; unresolved needs keep the typed refusal without starting OAuth. Concurrent node/profile expansion may call the host for the same provider more than once. The host must coalesce by its actual provider/account scope, honor the supplied signal and settle its work; Runtime adds no cache, Hub client, browser or OAuth wait. Resolution follows parameter/trigger binding and precedes topology validation, so supplying an effectful resolver does not guarantee zero effects for every invalid graph. Runtime validates canonical connection/profile shape; the host owns matching each connection to the intended provider/account.

Execution `allowedModels` checks every authored node’s model fields before the graph starts. Runtime’s deterministic flow coordinator makes no model call and needs no allowlist entry. Nested flow items retain the same real-node policy.

A data `check` uses the same `pointer`, `equals`, `in`, `exists` and `all` grammar as routes, with optional graph `node` selection. It judges the flow's terminal output map. Independent command checks use `deliverable: { checkRef: 'command', command: { command, timeoutMs } }`; trigger slots can select the command. Commands run through Runtime's maintained process port for each fresh leaf. Their real exit/output receipts live in a driver-owned `runDir` outside the jailed worker workspace, never in worker output. Remote Bridge and provider validators without an exact node binding refuse this command-check form. The host must also prove this driver directory is unreadable and unmounted in the worker and the command uses the actual worker filesystem; loopback addressing alone proves neither condition.

For durable runs use `superviseGraphPursuit` and its existing run directory lock, observer journal, spawn journal, result and failure records. Reuse the same run identity and directory after an interrupted process; do not replay a settled directory as new work. A gracefully cancelled run has a settled record: explicitly supply `reopen` with the operator, reason and stable operation identity to archive that segment and resume the same journal. Signal handling belongs to the CLI and aborts the run through its signal before exit.

Live observers receive `coordination.onReadReady`. Operators may separately receive `coordination.onControlReady`; `connectRemoteSupervisorControl` uses that protected grant to steer or cancel an exact owned worker through the existing coordination handlers. A read grant cannot become a control grant. Keep all access headers out of profiles, journals and public artifacts.

`graphDesignerProfile({ profile })` from `/profiles` preserves the caller's complete execution profile and composes the bundled graph-designer, agent-graphs and be-ambitious skill resources. It requires the caller's actual execution identity and capabilities. Skills stay separate resources through the standard materializer.
