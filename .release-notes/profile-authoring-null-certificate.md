`skills/profile-authoring` separates ending a run from crediting it. A null may end a run, but it counts as success only when a party outside the run reproduces its coverage certificate: the searched space as data (parameter ranges, enumeration or sampling method with seeds, bound reached), one row per cell, a calibration cell with positives, and the sha256 of the reproducer that printed the rows. The reproducer belongs to the check: it is registered before launch, the run never writes it, and the outside check reruns its own copy on the certificate's cells, never code from the run. One mismatched row refuses the certificate, and credit covers only the cells the check reran; a sample can refuse but never credits a cell nobody reran. A null without a certificate or a registered reproducer is recorded as stopped and unverified. Traps are written as what the held-back acceptance refuses, never as what the proxy passes. A worked example shows the pcn-power null as a certificate. A blind trial found that an in-run check accepting a documented null on its fields made that null the cheapest hack in 11 of 16 judgments (discovery-lab#1137).
