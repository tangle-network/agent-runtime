New edge-safe subpath `@tangle-network/agent-runtime/placement`: `placeExecution()` chooses the cheapest tier (`inference`, `loop`, `sandbox`) a unit of work's declared requirements and resolved profile allow, never reading the prompt, and returns a `PlacementRecord` (`chosen`, `policy: 'agent-placement/3'`, `reason`, `coveredAxes`, `rejected`). It is Platform's `agent-placement/2` moved here with identical decisions and reasons (the tier `worker` is named `loop`), plus two opt-ins: `vacuousAxes: ['permissions']` covers a deny-only permissions map, and `inlineSkills` covers profile skills on `loop`. A pinned harness always runs in the sandbox. `resumedPlacement`, `authoredPlacement` and `sandboxOnlyRequirements` keep a retry on the tier it began with. In `/tool-loop`, `executeToolCall(call, { progress })` lets a running tool report progress: `streamToolLoop` yields each update as `{ kind: 'tool_progress', toolName, toolCallId, update }` in order before that call's `tool_result`, and `runToolLoop` passes it to `onToolProgress`. Executors that take only the call are unchanged.
