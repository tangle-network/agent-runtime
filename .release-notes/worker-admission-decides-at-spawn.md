Worker admission decides more at spawn. An in-box runtime restart (`EXECUTION_INTERRUPTED`, or the sidecar's restart text) is an infra failure in the one platform-failure table, so it no longer counts toward the 2-attempt deterministic stop. A capacity pause reads the provider error's structured `resetAt` instead of message text, and a reset after the run's deadline stops the driver with the new typed stop `quota-unavailable` (an opted-in root pauses on it); `DriverAttemptStop` gains that member. The default per-worker share divides the reservable pool by `workerSlots` when slots are set (a quarter only without them), so slots, not the budget ledger, set how many children run at once. A live child's own `deadlineMs` counts from its budget and slot grant, not its spawn. Runtime's model-control check (unknown `model.metadata` keys, an ambiguous `maxTokens`) runs in the spawn preflight, so `spawn_worker` refuses such a profile as `unprovisionable-profile` before any reservation or box.
