A supervisor no longer exits when an accepted root turn's workspace capture fails (an expired Platform key, a Sandbox error page, a capture timeout). The failure is journaled once on the node as an `execution-evidence` row with `workspaceCaptureFailure`, the source environment is preserved and never mutated, the next turn starts in a new environment, and the run settles as it would. The release tries that capture once more: a capture that lands clears the debt and releases the source, and one that fails again keeps the source, named in `teardownUnconfirmed[].kept` with `keptFor: 'evidence'`. An unfinished input an older coordinator admitted into such a source, but never dispatched there, is journaled `execution-abandoned` (`outcome: 'uncertain'`) and replaced by a new invocation elsewhere. Before, each restart met the same failure: 66 supervisor starts in 17 runs, 76.7 wall-hours with nothing driving the run. A retained turn whose provider command (the credential command) exits non-zero before any dispatch is now a pause, never a pending invocation: its `driver-attempt` record has `classification: 'unavailable'`, `unavailableSignal: 'credential-unavailable'`, the command's `exitCode` and `resumeAt`, and it never counts toward `pending-unresolved`. Before, 306 such attempts stopped 10 nodes and lost 7 runs.
