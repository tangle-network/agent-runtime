The version chain also removed `JudgedPursuitVersion.improved`, `usd`, `usdKnown`, `usdSource` and `lineage`: read a version's spend and its edge from the chain's ledger (`versions.spend`, the `cell-settled` accounting and the `edge-recorded` diff, which holds the change with its own `source`). Fixed in the chain: an unscored version (a `null` judge score) is a final error and is not judged again, as before 0.281.0; 0.281.0 retried it up to 3 times, and the retries kept the version's hold open in the dollar rule. Aborting `signal` pauses the chain: the running version settles cancelled and is judged as it stands, and a later call continues from the kept version. A change that reproduces an earlier version's profile runs nothing new and counts toward `patience`. a first profile with undefined entries and a change with undefined entries are stored as JSON instead of failing the ledger's canonical encoding; a `deadlineMs` beyond year 9999, such as `Number.MAX_SAFE_INTEGER`, means no deadline instead of throwing `RangeError`; a version's `budget.maxUsd` is a hard hold, so the chain admits a version only when its whole budget fits; a settled directory is read back only when its root ran the chain's task and budget as well as the node's profile; a version whose signal already aborted is not started; `'review-of-best'` keeps exactly one review instruction when the review words have no placeholder; a version whose provider reported no cache split records its tokens as unknown instead of 0 cached; and each sealed `result.json` is read, hashed and parsed from the same bytes once per call.
