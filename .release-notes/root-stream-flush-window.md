The root stream, and each node stream, now writes the lines appended within a one-second window in one fenced write. It used to take the run's fsynced mutation lock for every line, and in 3.0.28 (#2332) for every event-loop turn, which still meant one upstream page of about 24 lines per fence. On Discovery runs whose run directory sits on a busy SMR drive, fences took 150 ms median and 1.8 s at p90. The relay drained 2.5 events/s per line (us-legal-exploits-20261103a) and about 20/s per turn (us-legal-exploits-20261103b), while the model streamed about 210 reasoning deltas/s, so the supervisor fell minutes behind its box with its main thread in disk wait. A process kill now loses at most the open window. A lost claim is still thrown to the next `append`, `beginAttempt` or `close`.
