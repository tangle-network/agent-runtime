Flow graphs fix three review findings. `runGraph` now refuses a flow graph in which any routes cycle crosses no edge with `maxTraversals`: one capped edge no longer bounds a whole strongly connected component, so a capped `a -> b` beside an uncapped `b <-> c` loop is refused before compute, and the `ValidationError` names the uncapped cycle's nodes (`b, c`). A stored graph keeps the flow graph's `entry` and `gates`: `recordGraphRun` stores and hashes them, `graphFromStored` restores them, and `run_graph` by `graphDigest` runs a stored flow graph exactly as it runs the inline form. Digests of graphs without `entry` are unchanged; a flow graph's digest now covers its entry. A killed flow graph restarted after its entry settled continues along the entry's outgoing route; that path shipped with flow-graph resume and is held by the kill-at-every-settle conformance test.
