A killed flow graph resumes from its run directory and runs no finished step twice. The route walker replays the flow from its spawn journal. A step whose done settlement is on disk comes back committed (`resumed: 'completed'`), and its result takes the live settle path at once: routes, maps and gates. An in-doubt step is re-admitted once under `<key>#2`, and a second in-doubt ends the run with `GraphResult.stopped.reason` `in-doubt:<node>`. A journaled gate decision is replayed without calling `decideGate`. Map item and join spawns are now keyed `map:<edge id>#<expansion>:<index>` and `map:<edge id>#<expansion>:join`, where expansion is the source node's 1-based done-settle count. This applies to every graph with a `maps` edge, root-driven graphs included: their journal spawn rows and assignment ids (`key:map:…`) carry these keys instead of `ordinal:<n>`. A map whose source settled before a kill now re-expands after the restart, runs only the items with no done settlement, and runs its join once. A journal written before this change holds unkeyed map rows, so a flow resumed from it runs those map items again.
