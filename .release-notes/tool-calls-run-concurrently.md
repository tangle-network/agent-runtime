`runToolLoop` and `streamToolLoop` take `maxConcurrentToolCalls`: a caller that sets it above 1 runs up to that many of one model turn's tool calls at once. The default stays 1, so every existing caller still runs a turn's calls one at a time. Calls start in call order; results, `tool_result` yields and tool messages keep call order, and each `tool_progress` names its own call and streams before that call's result. Hook events stay one before and one after per call. Once `maxCostUsd` is spent no further call starts, and the turn stops with `budget` after the calls already started settle; at width 1 that is the previous rule exactly. Opt in only where a turn's calls do not depend on each other finishing first.
