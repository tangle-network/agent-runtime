An `AgentGraph` can fan out over a list that exists only at run time. A `maps` edge (`{ kind: 'maps', from, pointer, to | graph, join, directive, maxItems, concurrency, onItemFailure, itemBudget? }`) runs one item per element of the array its JSON pointer selects in `from`'s settled result, through the same admission, pinning and conserved pool a spawn takes, then hands the `join` node `{ results, failures }` in item order. The driver spends no model turn on items or the join. `concurrency` throttles items and never refuses one; a list over `maxItems`, a pointer that does not select an array, or a concurrency above the run's worker slots is refused with a ledger row and wakes the driver. `onItemFailure: 'all-or-refuse'` stops starting items after a failure and refuses the join with the failures listed; `'settled-subset'` joins the delivered results with the failures beside them. An item may be a nested graph, started through the `run_graph` path. The edge ledger and its journal twin carry one expansion row, one row per item (with `map.index`) and one join row; `EdgeDeliveryOutcome` and the journal `edge` event add `failed` for an item or join that ran and did not deliver. Coordination gains the `map` event, `SuperviseOptions.mapOnSettle` (graph-owned in `runGraph`) and `WorkerSpawnContext.map`.
