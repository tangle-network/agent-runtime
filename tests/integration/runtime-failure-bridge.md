# Paired Runtime and Bridge failure proof

`runtime-failure-bridge.test.ts` runs Runtime against the public entry of an installed CLI Bridge package on an ephemeral loopback port. It imports no Bridge internals and replaces no HTTP handler, durable store, executor or protocol parser. The original five cases use the disposable `native-failure-protocol.cjs` OS executable through public `CLAUDE_BIN`: actual process stdout, exit and cancellation receipts, with no model or service calls. Its successful worker deliberately returns forged failure/remediation data, including an oversized remedy, which must never acquire Runtime authority.

The four subscription cases use a separate wrapper around the actual installed Claude binary. The wrapper delegates only a lone `--version` or read-only settings selectors followed by `auth status --json`; every other argument list records an attempt and exits before inference. A disposable HOME and public test settings exercise the genuine producer's signed-out, selected API-key and unverified bearer admission. The public `Config.subscriptionsOnly` setting is enabled by `BRIDGE_SUBSCRIPTIONS_ONLY=1`. Native status is never fabricated. This proves refusal before inference, not account validity, a subscription model turn, or native PATH portability inside a jail.

The qualifier targets Bridge merge `30861a2947beb93b03a11ebff3941f7d585808c7`, whose public source [archive](https://github.com/drewstone/cli-bridge/archive/30861a2947beb93b03a11ebff3941f7d585808c7.tar.gz) has SHA-256 `e9b34c46f0f11df5d798630c0c5a967eaa68170549abbc26ac0973cfae845b2f` and 935723 bytes. The producer manifest binds all 284 source files to the tested tree `5d3ee3a38d9836c45b72d77aa2241f471fb64691`; the native qualifier verifies this exact artifact before pairing it with the Runtime source SHA. The older PR283 artifact does not qualify the new guard. The combined fixture additions were authored source-only; native source/build/type/behavior proof was UNRUN at that freeze, and a passing producer gate alone supplies no Runtime consumer proof.

Supply `RUNTIME_BRIDGE_PACKAGE_ENTRY` as the installed package's public `index.mjs` entry URL and `RUNTIME_BRIDGE_NATIVE_CLAUDE_BIN` as the qualified actual native executable. The paired admission command fails explicitly if either is missing:

```sh
RUNTIME_BRIDGE_PACKAGE_ENTRY="${RUNTIME_BRIDGE_PACKAGE_ENTRY:?Supply the qualified installed public Bridge entry URL}" \
RUNTIME_BRIDGE_NATIVE_CLAUDE_BIN="${RUNTIME_BRIDGE_NATIVE_CLAUDE_BIN:?Supply the qualified actual Claude executable}" \
pnpm exec vitest run tests/integration/runtime-failure-bridge.test.ts
```

Run through the maintained gate on the admitted native host. The default suite without the package-entry variable explicitly skips this paired proof; it is distinct from the mandatory qualifying command. All nine cases must pass. The original five retain child native model/auth codes, unchanged `all-children-down` lifecycle, actual journal/replay/observer equality, protected HTTP reads, caller cancellation with confirmed process disappearance, and worker-payload non-authority. Legacy journal reasons remain unknown rather than decoding native prose.

The three native root cases compare the actual producer HTTP403 and SSE error403 values, exercise Runtime's shared decoder on the actual non-2xx response, and run a canonical two-node rooted graph with explicit Bridge worker and driver backends. They compare its selected `driver-failed` failure/remediation, returned done pursuit run, actual Runtime-written `result.json` and cold `FileObserverJournal` replay. If a competing lifecycle reason wins, the fixture fails with the actual result; it does not force a different reason or manufacture accounting. A fourth case reads the same validated remedy from an actual settled child through protected HTTP tree/observe. Metadata-process records and the absent inference-attempt marker accompany known-zero accounting assertions. A manual JSON write or merely nonempty journal is not durable proof.

Consumers read child `RuntimeFailureCause` from `runGraph(...).result.tree.nodes`, `superviseGraphPursuit(...).result.result.tree.nodes`, `RemoteSupervisorReader.tree()` and `.observe(workerId).agent`, `materializeTreeView`, `replaySpawnTree` down settlements, and `projectPursuit(...).nodes`. A selected root `no-winner/driver-failed` carries optional `error.failure`; the durable pursuit's existing run projection carries the same optional failure. A returned no-winner run remains done. Legacy absent facts remain absent.

`code`, `owner` and optional `providerCode` are machine values; `cause` is bounded redacted display text. Optional `remediation` is the producer's validated cause/fix/harness/provider value, never recovered from prose. Actual non-2xx HTTP status wins over conflicting body claims; SSE remediation needs explicit structured403. The whole-response byte bound applies to non-2xx HTTP buffering, while structured field bounds apply to both decoder paths. No general SSE-wide response cap is claimed.

The existing loader's `resolveSeat` receives `context.lastCandidate`. It is true for a sole explicit or global override, the final item of an authored ordered preference list, and the implicit default choice. Returning undefined allows an earlier unavailable preference to fall through; errors still propagate unchanged. Bridge's resolver may return its structured login refusal for the final unavailable preference without Runtime parsing that refusal.
