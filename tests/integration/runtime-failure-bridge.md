# Paired Runtime and Bridge failure proof

`runtime-failure-bridge.test.ts` runs Runtime against the public entry of an installed CLI Bridge package. It starts the real server on an ephemeral loopback port and selects the disposable `native-failure-protocol.cjs` executable through the public `CLAUDE_BIN` configuration. The executable emits native protocol frames and actual process exit receipts; it makes no model or service calls. The test does not import Bridge internals or replace its HTTP handlers, execution, durable store or protocol parser.

The native qualifier must supply `RUNTIME_BRIDGE_PACKAGE_ENTRY` as the public `index.mjs` entry URL of the installed, qualified Bridge artifact and record that artifact's source commit and archive digest beside the Runtime source commit. The intended starting pair is Bridge PR283 commit `355646b650a8fb167e48bcd24c2dab28325c3194` (or its qualified merged successor) and this Runtime fix. No artifact was installed or executable proof run when this fixture was authored. Without the variable, this paired suite explicitly skips and supplies no qualification evidence.

For the paired gate, fail admission when the artifact is absent: `RUNTIME_BRIDGE_PACKAGE_ENTRY="${RUNTIME_BRIDGE_PACKAGE_ENTRY:?Supply the qualified installed public Bridge package entry URL}" pnpm exec vitest run tests/integration/runtime-failure-bridge.test.ts tests/integration/graph-file.test.ts`. Use that command on the admitted native host. The default suite without the variable explicitly skips this paired proof and remains distinct from this mandatory paired gate. The proof must pass all five paired cases, including both refusal cases. Expected results are exact upstream codes on `tree.nodes[].failure`, unchanged `no-winner` / `all-children-down` lifecycle, equality after journal replay and observer projection, protected HTTP tree and observation equality, caller cancellation with confirmed process disappearance, and no authority from a worker-authored `failure` field. The pre-field journal case must remain `unknown` rather than decoding native prose.

Consumers read `RuntimeFailureCause` from the existing terminal node: `runGraph(...).result.tree.nodes`, `superviseGraphPursuit(...).result.result.tree.nodes`, `RemoteSupervisorReader.tree()` and `.observe(workerId).agent`, `materializeTreeView`, `replaySpawnTree` down settlements, and `projectPursuit(...).nodes`. `code`, `owner` and optional `providerCode` are machine values. `cause` is bounded redacted display text. No remedy is synthesized from that text. A missing legacy field or a legacy reason alone supplies no native error code.

The existing loader's `resolveSeat` receives `context.lastCandidate`. It is true for a sole explicit or global override, the final item of an authored ordered preference list, and the implicit default choice. Returning undefined allows an earlier unavailable preference to fall through; errors still propagate unchanged. Bridge's resolver may return its structured login refusal for the final unavailable preference without Runtime parsing that refusal.
